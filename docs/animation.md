# 动画设计

本文是揭晓动画的修订版设计，已按[系统设计](system/design.md)第四节第 4 小节的接口和技术限制解决原稿中的冲突。原稿及冲突清单见[动画设计 · 原稿](animation_original.md)，修改对照见第八节。

## 一、定位

```
首页 → 答题 Q1..Q10 → 揭晓动画 → 结果页 → 电子卡页 → 保存分享图
```

- 第 10 题作答后进入揭晓。结果此时已经算出，动画只负责呈现，风格是“抽卡或开盲盒式的短动画”。
- 时长由最后一组元素淡入的结束时间决定。当前正常时长为 6.18 秒，等图时间另计。
- 只使用无文字版角色图。
- 手机和电脑使用同一套时间轴，窥视孔和窥视圈按角色图比例定位。
- 窥视孔展开前及等图期间使用全屏纯黑背景，展开时淡回结果页背景。

## 二、核心思路

1. **局部窥视代替放大特写**。原稿把角色图放大 5.5 倍做特写，源图宽度不够，画面一定发糊。修订版让角色图始终保持 1 倍或更小，只通过一个圆形窥视孔露出局部：先让人看到清晰的一小块，再把孔扩开露出全身。角色图全程停在结果页中的位置，窥视孔直接开在它的取景点上，不把角色移到屏幕中央。
2. **圆孔直接显示清晰角色图**。角色图加载并解码后，噪点淡出，角色图在圆孔内直接淡入。图未就绪时延长开场噪点阶段。
3. **大面积只动 `transform` 和 `opacity`**。这两个属性由合成线程处理，不触发重排和重绘，在中低端安卓上也能保持流畅。唯一的例外是窥视孔的 `clip-path`，它只作用在角色图元素上，面积不超过角色图本身。
4. **结束帧就是结果页第一帧**。揭晓和结果页渲染同一套结果页布局，揭晓时只是在这套布局上叠加动画。动画全部结束或被取消后，元素回到自身的样式，也就是结果页的样子，中间不切换画面。

## 三、时间轴

除特别注明外，各阶段首尾相接，没有重叠。

| 时间（秒） | 阶段 | 画面 | 实现要点 |
| :--- | :--- | :--- | :--- |
| 0.00–0.20 | 噪声建立 | 角色图所在区域浮现颗粒噪声，大小约等于角色图 | 噪声层 opacity 0→0.85 |
| 0.20–1.00 | 噪声跳动 | 噪声持续变化；噪声下方文案淡入 | 噪声层每 40 ms 跳到一个随机偏移（translate，`steps` 缓动）；文案 opacity 0→1，600 ms |
| 1.00–1.20 | 蓄力 | 噪声一次明暗脉动 | 噪声层 opacity 0.85→1→0.85，scale 1→1.04→1 |
| 1.20–1.65 | 显露角色局部 | 圆孔内直接出现清晰角色图 | 原图和窥视圈淡入，噪点和文案淡出 |
| 1.65–2.83 | 窥视 | 圆孔略微放大 | 窥视孔和窥视圈从完全露出时同步扩大到原半径的 1.03 倍 |
| 2.83–3.20 | 收缩蓄力 | 圆孔和外圈向中心收紧，停半拍 | 到 3.11 秒缩到原半径的 72%，保持 90 ms |
| 3.20–3.90 | 展开 | 窥视孔原地扩开露出全身，黑底淡回结果页背景 | 半径扩到覆盖整张图，700 ms，`cubic-bezier(0.16,1,0.3,1)`。窥视圈放大到 1.7 倍并淡出，3.20–3.50 |
| 3.72–4.18 | 落定 | 角色轻微缩小后回弹 | 内层 scale 1→0.97→1，与展开末段重叠 180 ms |
| 4.18–4.73 | 人格名 | 人格名落下 | translateY −12px→0，scale 1.04→1，opacity 0→1 |
| 4.73–5.53 | 四维条 | 四条依次填充到目标长度，字母和极名随条出现 | 每条 440 ms，间隔 120 ms，从条形中线向得分方向伸展 |
| 5.53–6.18 | 描述与其余内容 | 四维条播完后，描述、按钮等内容一起上移淡入 | translateY 8px→0，opacity 0→1 |

`正在读取你的 10 个选择…` 从 0.20 秒起淡入，等图期间保留，在圆孔出现时淡出。

角色图从头到尾停在结果页中的位置，不做平移。噪声层罩在角色图所在的区域，窥视孔开在角色图的取景点上，文案放在噪声下方，与角色图左右居中对齐，不超出视口。电脑布局中这些都跟着角色图出现在左栏，不在屏幕正中。

四维条的目标长度取自结果页四维条本身（长度比例为 |得分| ÷ 7），动画只是它的入场，最终长度不由动画决定。

## 四、等待与异常

| 情况 | 行为 |
| :--- | :--- |
| 1.20 秒时角色图尚未加载并解码 | 保持黑底，噪点继续跳动，提示文案保留。图片就绪后从 1.20 秒接着播放 |
| 进入揭晓后 8 秒仍未加载完 | 结束揭晓，进入结果页，显示加载失败与重试 |
| 角色图加载出错 | 立即结束揭晓，进入结果页，显示加载失败与重试 |
| 点击、触摸、按键或浏览器后退 | 揭晓继续播放 |
| `prefers-reduced-motion: reduce` | 保留完整时间轴和淡入淡出。噪声静止，窥视孔在 3.2 秒直接打开，省去收缩、回弹和条形伸展 |
| 旋转屏幕或调整窗口 | 窥视孔和窥视圈按新布局定位，继续播放 |
| 切到后台 | 按浏览器的动画时间轴继续，达到结束时间后进入结果页 |

播放完成或加载失败时，清理动画并派发 `REVEAL_DONE`。元素回到结果页样式，焦点移到人格名。

角色图在第 10 题作答后才开始预加载（系统设计第四节第 5 小节），噪声阶段的 1.2 秒正好作为加载窗口。

## 五、8 个角色的窥视取景

窥视孔里的局部要有辨识度，但看不出是谁。除 DeepSeek 和 Gemini 取角色自身外，其余只取道具，尽量少露出角色。

| 角色 | 窥视对象 | 类型 |
| :--- | :--- | :--- |
| GPT | 图纸一角：图框、细网格、折角 | 道具 |
| DeepSeek | 鲸尾 | 角色自身 |
| Claude | 案卷封套的装订边 | 道具 |
| Kimi | 手风琴折页的连续折痕 | 道具 |
| Gemini | 一只眼睛（异色瞳） | 角色自身 |
| GLM | 键盘，几个键帽被压住 | 道具 |
| Grok | 气球：紧绷、被顶出一处凹陷 | 道具 |
| 豆包 | 奶茶杯口：封膜、吸管孔 | 道具 |

三张纸要区分开：GPT 是冷白底加灰色网格的工程图纸；Claude 是米黄纸加装订孔的正式案卷；Kimi 是偏白纸带加等距竖直折痕的折页。三者容易混淆，这本身有利于制造悬念，但各自的材质必须成立。

由于画面不放大，窥视对象在角色图中必须本身就足够大，能在 1 倍下看清。半径建议在图宽的 12%～20% 之间；以手机上角色图宽约 340 CSS px 计，对应直径约 80～135 CSS px。

## 六、实现方式

| 项 | 方式 | 理由 |
| :--- | :--- | :--- |
| 时间轴 | Web Animations API（`element.animate`）。各段使用毫秒标注，总时长取最后一段的结束时间 | 支持等图、中途接续和结束时清理。调整前一段时间后，后续相连的段随之移动 |
| 噪声 | 运行时用 canvas 生成一张 128 × 128 的灰度噪声图，平铺在噪声层上；只做平移跳动 | 噪声只计算一次，之后每帧只是移动一个合成层 |
| 角色入场 | 原图完成解码后在圆孔内淡入 | 窥视与展开阶段使用同一张清晰角色图 |
| 窥视孔 | 角色图元素上的 `clip-path: circle()` | 作用面积只有角色图本身 |
| 定位与缩放 | 角色图分三层：外层只负责定位，不做动画；中层做落定的缩放；内层是窥视孔裁切 | `transform` 和 `clip-path` 写在不同元素上，互不覆盖 |
| 四维条 | `transform: scaleX()` | 动画 `width` 会每帧重排 |
| 取景参数 | 界面层中单独的一个数据文件 | 校准时只改一处 |

噪声层和窥视圈是装饰元素，设 `aria-hidden="true"`。

## 七、验收要点

在[测试与验收](system/verification.md)第二节的基础上，揭晓动画另外检查：

- 中低端安卓手机上全程流畅，没有明显卡顿。
- 窥视阶段孔内画面清晰，展开后的全身图与结果页中的完全一致，结束时没有跳动或闪烁。
- 8 个角色的窥视对象都能看清，同时猜不出是哪个角色。
- 窥视孔展开前及等图期间，角色动画之外的区域为纯黑。展开时显露结果页背景。
- 揭晓不能手动跳过。调整布局后，窥视孔和窥视圈仍对齐，播放结束后没有残留的模糊、裁切或位移。
- 限速网络下噪声阶段会等图；断网时 8 秒内进入结果页并显示重试。

## 八、相对原稿的修改

| 原稿的问题 | 修改 |
| :--- | :--- |
| 5.5 倍放大特写会发糊 | 改为 1 倍下的圆形窥视孔，全程使用同一张清晰角色图 |
| 逐帧变化的 `feTurbulence` 和 `feDisplacementMap` 覆盖大面积 | 噪声改为一次生成、只做平移的平铺图；位移效果改为 opacity 与 scale 脉动 |
| 等图没有上限 | 8 秒超时进入结果页并显示重试；加载出错时立即进入 |
| 拉远、过冲、回弹、定格的时间互相重叠 | 重排为首尾相接，只保留“落定”与“展开”末段的 0.1 秒有意重叠 |
| 四维条“每条 300 ms、间隔 80 ms”放不进 0.3 秒 | 改为每条 220 ms、间隔 60 ms，共 0.4 秒 |
| 人格名动画改字距，每帧重排 | 改为 scale 1.04→1 |
| 0.8 秒处“顶部文案切换”没有写切换成什么 | 只保留一句文案 |
| 连续掉帧时降级为简版 | 删除。动画只用合成线程处理的属性，主线程 `requestAnimationFrame` 测到的帧耗时不能反映它是否卡顿；真机验收确认流畅即可 |
| 不支持 `backdrop-filter` 时用纯色替代 | 删除，修订版不使用 `backdrop-filter` |

### 样板验证后的调整（2026-11-20）

修订版在样板页中实现后，按实际观感又改了两处：

| 修订版初稿 | 调整 |
| :--- | :--- |
| 窥视阶段把角色图平移到视口中央，展开时再移回结果页中的位置 | 角色先移走再移回，观感不自然。改为角色图全程不动，噪声和窥视孔都放在角色图原位 |
| 正常时长 3.0 秒 | 节奏太快。整体放慢一倍为 6.0 秒，各阶段的顺序和比例不变；等图的判断点相应从 0.6 秒移到 1.2 秒 |
