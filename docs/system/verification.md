# 测试与验收

本文定义网页的自动化测试和真机验收。约束见[现实约束与要求](requirements.md)，被测对象见[系统设计](design.md)。

## 一、自动化测试

在 `web/` 执行 `npm test`，部署工作流在构建前运行，不通过则不部署。

### 1. 内容

- `tsc --noEmit` 通过。
- [系统设计](design.md)第二节第 3 小节的全部校验规则，包括两个 JSON 的结构、16 个代号恰好各一份，以及题目权重与手写计分表的交叉检查。每条规则另配一份故意写错的测试数据，确认能检出。例如：删掉一个代号、把权重写成 3、把 `modelId` 拼错、把某题的主测维度权重写成 1，测试都必须失败。

内容与文档不再比对，也没有发布前的逐条核对清单。但首次导入有一次人工审阅，在提交第一版 JSON 之前完成：

- [ ] 运行 `scripts/import-content.ts` 后，对生成的 JSON 与 [tests_design.md](../tests_design.md)、[result_page.md](../result_page.md) 逐项抽查：10 道题的题干、选项（文档中【】括起的标题不导入），40 个选项的权重，16 个人格的名称、对应模型和描述
- [ ] 手写的 `dimensions.ts` 中的 4 个维度名、8 个极名和计分表，对照 [aiti_personality.md](../aiti_personality.md) 和 [tests_design.md](../tests_design.md) 第一节逐项核对
- [ ] 描述中的强调和等宽片段（如 `Segmentation Fault`、`git diff`）已转成 `Segment[]`，文本里没有残留 `**` 或反引号
- [ ] 审阅时发现的差异，以文档为准改脚本后重新生成，不手改 JSON，也不让模型重新输入文案

此后修改题目和人格文案，直接改 JSON 并提交，由提交审查把关。

### 2. 计分

- **穷举**：遍历 4¹⁰ = 1,048,576 种作答组合，断言每个维度得分都不为 0，且 16 个代号都能得到。按当前题库，16 个代号各占 6.25%，测试同时输出分布供内容负责人参考，但不把均匀分布作为断言。
- **固定用例**：手算若干组作答的四维得分和代号，作为回归用例。
- **四维呈现**：得分 ±1、±3、±5、±7 对应的 `side`、`letter`、`poleName`、`ratio` 正确。

### 3. 流程状态机

- 第 1 题 `BACK` 回到 `intro`；第 2～10 题 `BACK` 回到上一题且保留原答案。
- 题号不一致的 `ANSWER` 被忽略。
- 第 10 题作答后进入 `reveal`；`REVEAL_DONE` 进入 `result`。
- `RESTART` 清空答案并回到 `intro`。

### 4. 分享图

- 「保存图片」位于「再测一次」之前，打开后显示本次结果的 JPEG。关闭窗口恢复按钮焦点。
- 分享卡和结果页按人格代码读取同一个 `description` 字段，正文一致。
- 四维项从中线向亮起的一侧延伸，两端字母与中文极名横排。
- 宣传图素材在窗口打开时加载。模拟底图加载失败后，窗口可重试。

### 5. 构建产物

- 首屏 JS、CSS 和各类图片未超出上限。
- 产物中不含原始素材，不含未压缩的 PNG 角色图。
- 发布构建未设置 `AITI_ALLOW_PLACEHOLDER`；DeepSeek、Grok、豆包使用的是无文字版。

## 二、真机验收

在线上地址 `https://gmh06.github.io/AITI/` 上进行。手机环境：iPhone Safari、iPhone 微信、Android Chrome、Android 微信。电脑环境：Windows 上的 Chrome 或 Edge、macOS 上的 Safari。

### 1. 共通项

手机与电脑环境都要检查：

| 项 | 预期 |
| :--- | :--- |
| 完整流程 | 首页 → 10 题 → 揭晓 → 结果 → 保存图片窗口，无报错 |
| 回退 | 应用内回退和系统返回键行为都与[系统设计](design.md)第四节一致 |
| 刷新 | 任意状态刷新后回到首页 |
| 快速连点 | 同一题连点只前进一题 |
| 揭晓 | 前 3.2 秒及等图期间全屏纯黑，圆孔内由模糊转为清晰，展开时显露结果页背景；揭晓不可跳过，开启“减少动态效果”时仍走完整时间轴 |
| 四维 | 每条两端都显示字母和中文极名，条形方向、长度和高亮端与得分一致；全页没有分数和程度词 |
| 保存分享图 | 微信内长按可保存；Safari、Chrome 通过保存按钮可存入相册或下载 |
| 分享图可读 | 保存的图片通过微信发送给他人后，文字仍清晰可读 |
| 加载 | 手机 4G 下首屏 LCP ≤ 2.5 s |
| 图片失败 | 断网后进入结果页，显示失败状态，恢复网络后可重试 |

### 2. 手机

| 项 | 预期 |
| :--- | :--- |
| 屏幕宽度 | 宽 360、390、430 CSS px 下各走一遍，无横向滚动，内容不被截断 |
| 安全区 | 有刘海和底部手势条的 iPhone 上，内容和按钮不被遮挡 |
| 微信工具栏 | 微信内关键按钮不被底部工具栏遮挡 |
| 横屏 | 横屏后内容可完整查看和操作；旋转前后状态和答案不丢失 |
| 双击 | 快速双击选项不会触发页面缩放 |

### 3. 电脑

| 项 | 预期 |
| :--- | :--- |
| 窗口尺寸 | 1280 × 720 与 1920 × 1080 下各走一遍，使用电脑布局，无横向滚动，内容不被截断 |
| 跨阈值缩放 | 答题中把窗口拖窄到手机布局再拖宽，布局随之切换，当前题目和已选答案不变 |
| 键盘 | 只用 Tab、Enter、空格完成完整流程；切换题目后焦点落在新题内容上；揭晓期间按键不会提前显示结果，播放结束后焦点落在人格名 |
| 后退 | 浏览器后退按钮的行为与应用内回退一致 |
| 图片清晰度 | 在高分屏（`devicePixelRatio` 为 2）上，角色图不明显发糊 |
| 保存分享图 | 保存按钮可下载图片；右键另存可用 |
