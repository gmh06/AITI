# AITI 系统总览

本文定义 AITI 网站的整体形态、边界与关键流程。页面细节见 [页面与交互](pages.md)，内容与文案见 [内容与版本](content.md)，技术实现见 [技术方案](tech.md)，排期与验收见 [实施计划](plan.md)。

## 一、一句话定位

AITI 是清华大学计算机科学与技术系第44届学生节「Beyond Context」路演现场的一个纯前端人格测试网站。参与者用手机扫码或现场电脑完成 10 道校园情境题，页面按固定规则算出 16 种 AI 人格之一，展示对应的 AI 角色、四维倾向和电子纪念卡，并提供可保存的分享图。

## 二、系统边界

### 做什么

| 能力 | 说明 |
| :--- | :--- |
| 答题与计分 | 10 道题，纯规则计算，全部在浏览器内完成 |
| 结果展示 | 16 种人格各一版固定内容：AI 角色、人格名称、四维倾向、描述文案 |
| 电子卡 | 可翻转，正反两面展示角色与人格信息 |
| 分享图 | 电子卡的正反面排版在同一张图上，可直接保存 |
| 结果链接 | 每种人格有固定地址，可直接分享 |
| 现场大屏 | 静态轮播页，展示玩法、二维码与 AI 角色 |

### 不做什么

| 不做 | 原因 |
| :--- | :--- |
| 后端、数据库、账号体系 | 结果完全由答案决定，不需要服务端参与计算 |
| 昵称与任何个人信息 | 产品上不需要，也避免隐私问题 |
| 测试记录与统计 | 同上，现场不做数据收集 |
| 后台管理 | 内容以代码形式维护，改内容即改站点 |
| 调用大模型 | 匹配是固定规则，结果秒出，且离线也能计算 |
| 针对答案的个性化文案 | 同一人格的人看到完全一样的内容 |

## 三、三个使用场景

1. **参与者手机**（主）——扫现场二维码进入，是主要流量来源。
2. **现场电脑**（辅）——1～2 台体验机，一位结束后回到首页。
3. **现场大屏**（展示）——独立的全屏页面，与答题页分开运行。

## 四、一次测试的生命周期

```
首页 → 答题 Q1..Q10 → 计算四维得分 → 抽卡动画 → 结果页 / 电子卡 → 保存分享图
```

| 阶段 | 地址 | 说明 |
| :--- | :--- | :--- |
| 进入 | `/` | 活动标题、一句话玩法、开始按钮 |
| 答题 | 同页 | 一页一题，进度 1/10，可回退修改答案 |
| 计算 | — | 10 题选项累加四维得分，各取符号得到 16 个代号之一 |
| 揭晓 | 同页 | 短动画，可点击跳过 |
| 结果 | `#/r/{CODE}` | 角色、人格名称、四维倾向、描述、电子卡、保存按钮 |
| 重测 | 回 `/` | 允许重复作答，不留下任何记录 |

异常分支：

| 情况 | 行为 |
| :--- | :--- |
| 答题中途刷新或关闭页面 | 进度作废，回到首页重新开始 |
| 直接访问任一结果地址 | 正常展示该人格的结果 |
| 未作答就点下一题 | 不允许前进 |
| 同一人重复作答 | 允许，不产生任何记录 |

## 八、已知风险

| 风险 | 影响 | 应对方向 |
| :--- | :--- | :--- |
| GitHub Pages 国内访问不稳定 | 现场扫码打不开页面 | 提前一周每日测速，准备现场备用方案 |
| 二维码在实物卡上的可扫性 | 卡片上只有二维码、没有文字网址兜底，扫不出即无法参与 | 纠错等级取 Q，尺寸不小于 2.5cm，印刷前用实物测扫 |
| 断网或服务异常 | 现场无法参与 | 备用流程见[实施计划](plan.md) |
