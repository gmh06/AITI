# 现实约束与要求

本文记录 AITI 网页必须满足的外部条件、产品边界和指标，不写实现方式。实现见[系统设计](design.md)，验收见[测试与验收](verification.md)。

范围只包括网页的编写与部署。图片、卡片、海报、二维码等物料的制作，以及现场执行，不在这三份文档内；网页用到的图片作为外部输入，只约定格式和存放位置。

每条注明来源。“既有决定”是团队已拍板的取舍，修改须重新确认；“客观条件”是无法通过方案改变的事实。

## 一、使用场景

| 场景 | 要求 | 来源 |
| :--- | :--- | :--- |
| 参与者手机 | 主要流量；扫码进入 | 既有决定 |
| 现场电脑 | 与手机打开同一网页、走同一流程，使用电脑布局（见第二节） | 既有决定 |
| 面向人群 | 以清华同学为主，题目与文案围绕校园和计算机系生活 | 既有决定 |
| 路演之后 | 线上测试继续开放；保留期限待定 | 既有决定 |

## 二、终端与网络

| 项 | 约束 | 来源 |
| :--- | :--- | :--- |
| 手机与电脑 | 网页须分别适配手机和电脑：两类设备功能一致，各有针对其屏幕和输入方式的布局。手机以竖屏触控为主；电脑为横向屏幕，用鼠标和键盘操作 | 既有决定 |
| 屏幕范围 | 手机竖屏宽 360～430 CSS px，横屏可正常使用；电脑窗口 1280 × 720 至 1920 × 1080。范围内任何尺寸都不出现横向滚动或内容被截断 | 既有决定 |
| 微信内置浏览器 | 主要入口，功能须与普通浏览器一致 | 既有决定 |
| 微信保存图片 | 网页无法触发下载，只能靠长按图片保存 | 客观条件 |
| 支持范围 | iOS Safari 15+、Android Chrome 100+、桌面 Chrome / Edge / Safari 最新版 | 既有决定 |
| 网络 | 以手机 4G 和校园网为主；高峰时可能几十人同时访问 | 客观条件 |
| GitHub Pages | 国内访问时快时慢，存在打不开的可能；不设备用站点，接受该风险 | 客观条件 / 既有决定 |
| 动画 | 揭晓须完整播放，前 3.2 秒使用纯黑背景，须尊重系统的“减少动态效果”设置 | 2026-11-21 修订 |

## 三、产品边界

以下各项已确认不做，方案中不应重新引入：

| 不做 | 原因 |
| :--- | :--- |
| 后端、数据库、账号 | 结果完全由答案决定，不需要服务端 |
| 昵称与任何个人信息 | 产品上不需要，同时避免隐私问题 |
| 测试记录与统计、后台管理 | 不做数据收集；内容以代码维护 |
| 调用大模型 | 固定规则匹配，秒出结果 |
| 按答案生成的个性化文案 | 同一人格看到完全一样的内容 |
| 结果链接与分享页 | 唯一的分享物是保存下来的分享图 |
| 大屏与展示页 | 现场没有大屏 |
| 体验机模式、开发调试页等其他运行模式 | 网页只有参与者模式一种；手机与电脑的区别只在布局和输入方式 |
| 续答恢复 | 刷新或关闭即回首页，进度作废 |

允许重复作答，不留任何记录。同一组答案始终得到同一结果。

## 四、内容

| 要求 | 来源 |
| :--- | :--- |
| 题目和 16 个人格的描述长文存为 JSON 数据文件，上线内容以 JSON 为准；其余文字（维度名、极名、界面文字）写在代码中。构建和运行时都不读取、不解析 Markdown 文档 | 既有决定 |
| 第一版 JSON 由开发期的一次性转换脚本从 [tests_design.md](../tests_design.md) 和 [result_page.md](../result_page.md) 生成，经人工审阅后提交；此后 JSON 与文档各自独立，不再同步和比对 | 2026-11-20 修订（修订前为“在文档中定稿后同步到数据文件，上线时两者一致”） |
| 16 个人格各一版固定内容，8 个 AI 角色各对应两个人格 | 既有决定 |
| 揭晓动画与结果页的角色图内不得出现任何文字 | 既有决定 |
| 结果页和分享图的四维条两端均标注字母和中文极名，测得的一端高亮。两处均省略程度词和分数 | 沿用视觉样板 |
| 分享卡沿用铭文卡的纸纹、字标和二维码，展示当前角色、人格代号及本次答题的四维。分享卡和结果页的正文共用该人格的 `description` | 分享卡视觉与共用人格文案 |
| 角色形象采用非人形方案，豆包沿用人形 | 既有决定 |

## 五、外部输入的素材

网页使用以下素材，均由他人制作，网页只读取并压缩：

| 素材 | 位置 | 现状 |
| :--- | :--- | :--- |
| 揭晓和结果页角色图 ×8 | [角色取用索引的 `transparent` 路径](../../asset/nonhuman/cards/source-map.json)，无文字，保留原尺寸 | 八张已归档 |
| 分享卡素材 | 铭文纸纹、字标、八款透明角色图、主视觉衍生城市图和卡背二维码，见[系统设计](design.md)第五、六节 | 已接入结果页保存窗口 |
| 主视觉 | `asset/Festival/` | 已有；网页是否使用、怎么用待界面设计确定 |

素材在仓库中保留原始文件，网页只引用构建压缩后的产物。素材未到位时，网页用占位图开发和测试。

## 六、性能与体验指标

| 指标 | 目标 |
| :--- | :--- |
| 首屏 JS（gzip） | ≤ 150 KB |
| 首屏 CSS（gzip） | ≤ 20 KB |
| 首屏图片 | ≤ 200 KB |
| 4G 下 LCP | ≤ 2.5 s |
| 结果相关的图片加载 | 结果页下载 1 张角色图，打开保存窗口后再按需下载宣传图素材 |
| 可点区域 | 手机上不小于 44 × 44 px |
| 键盘操作 | 电脑上完整流程可只用键盘完成，焦点位置始终可见 |
| 正文对比度 | 不低于 4.5:1 |
| 字体 | 分享卡字体随站点发布，打开保存窗口时按需加载 |
| 内容更新 | GitHub Pages 对所有文件固定返回 `Cache-Control: max-age=600` 且不可配置，新版本最多约 10 分钟后对所有访客生效 |
